    First run

    Install the local component

    number keeps the key that signs your board on this device, in a small Freenet component called a delegate. This node does not have it yet, so number cannot create or open a board here.

    • 01

      What installs

      The component is copied from this site onto this Freenet node. It runs locally, and only this app can call it.

    • 02

      What stays local

      The signing key it holds stays on this device and is never sent to a server.

    • 03

      What comes next

      Installing is a prerequisite, not your identity. Afterwards, number asks you to create a new owner key or restore a backup.

    Owner identity

    Set up this device

    This device has no owner key yet. The key signs every board change and decides which board you see. It is kept in this device's Freenet delegate, not on a server.

    01 Start fresh

    Create a new identity

    Starts an empty board owned by a new key on this device. Choose this if you have not used number before.

    02 Already have a board

    Restore from a backup

    Use the backup code from the device that owns your board. Restore first: this device can hold only one identity, and it will not replace one later.

    Nothing is created until you choose. You can back up the key later from the Identity row.

    Paste your backup code

    Paste the JSON code exactly as it was saved. The board uses the key inside it, so only do this on a device you trust.

    The code is JSON whose kind is number-identity, and it contains the private key. Do not paste it anywhere you do not control.

    Owner identity

    Back up your identity

    The backup code carries this board's owner key to another device. Keep it somewhere safe; there is no recovery server.

    Restore is not available here

    This device already has an identity, so it cannot import a backup. To use the same key on another device, open number there and choose Restore from a backup before it creates an identity, then check that the Identity in the header matches this one. The backup carries the key, not the board: the new device loads the board from Freenet, so it needs network access.
